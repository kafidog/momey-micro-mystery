# Playtest instructions — A1.1 capture plan

## Setup

1. Start a read-only static server at the repository root.
2. Open `/playable-a1/` or share the three seat links privately.
3. Put three people in the same physical room.
4. Each person opens one seat on their own phone; do not show the screen to another player.
5. Agree that each person will speak in their own words after reading each private card.

## Run

- Seat 1 uses `seat-1.html`, Seat 2 uses `seat-2.html`, Seat 3 uses `seat-3.html`.
- At Stage 3, first discuss what `0 已確認人員` could mean. Only then check the discussion box and open the system definition.
- At Stage 4, talk about which question matters more, then choose A or B verbally before each phone selects the same option.
- At Stage 5, 人員訊號席 says the P-side cost, 封鎖風險席 says Q's cost, 事件指揮席 restates the unresolved tradeoff, and the group talks freely before checking agreement.
- Read the complete P/Q consequence aloud together.

## Technical checks

- Refresh at Stage 2, the Stage 3 prompt, after the Stage 3 definition opens, Stage 4, and Stage 5.
- Use the two-step reset only after the complete end; verify one seat reset does not alter the other seats.
- Check desktop, iPhone-like 390×844, and Android-like 412×915 widths for overflow and reachable buttons.
- Record console errors and DOM/visual evidence outside the repository. This file is a capture plan, not a claim that screenshots already exist.

This is a synthetic/technical walkthrough. Do not convert it into human-fun, demand, WTP, E3, or E4 evidence.
